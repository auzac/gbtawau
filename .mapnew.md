# Repository Overview

A single-page web application for **Gereja Baptis Tawau** (GBT Church, Tawau, Sabah, Malaysia). Dual-purpose: public-facing church website with event listings and service rosters, plus a password-protected internal staff portal for managing members, content, finances, and worship sessions. Built with Vite + React 18, backed by Supabase (PostgreSQL + Auth), styled with Tailwind CSS via CDN, deployed on Vercel.

- **Repo name**: `gbtawau` (from `package.json`)
- **Type**: Vite SPA (no SSR, no API routes — all backend logic in Supabase)
- **Language**: JavaScript (JSX), JSON
- **Primary deps**: `react`, `react-dom`, `react-router-dom`, `@supabase/supabase-js`, `@splidejs/splide`, `lucide-react`
- **Dev deps**: `vite`, `@vitejs/plugin-react`, `tailwindcss`, `autoprefixer`, `postcss`
- **Deployment**: Vercel (`vercel.json`), output `dist/`, all routes rewritten to `/` (SPA fallback)
- **Branch**: `main` (clean, 7 commits past baseline)

# Core Entry Points

### 1. `index.html` — HTML Shell
- Google Fonts (Lora, DM Sans, Darker Grotesque) loaded once in `<head>`
- Tailwind CSS from CDN (`cdn.tailwindcss.com`)
- Mount point: `<div id="root">`
- Script entry: `<script type="module" src="/src/main.jsx">`

### 2. `src/main.jsx` — JS Entry Point
- Renders `<LocaleProvider><App /></LocaleProvider>` inside `<React.StrictMode>`
- No service worker, error boundary, or analytics

### 3. `src/App.jsx` — Root Component & Router
- Wraps in `<BrowserRouter><AuthProvider><AppRoutes /></AuthProvider></BrowserRouter>`
- `ProtectedRoute` checks `useAuth().user`; shows `LoadingSpinner` while loading, redirects to `/login` if unauthenticated
- Route table:

| Path | Component | Auth Required |
|---|---|---|
| `/` | LandingPage | No |
| `/login` | Login | No |
| `/staff` | StaffHub | Yes |
| `/staff/members` | MemberManager | Yes |
| `/staff/content` | ContentManager | Yes |
| `/staff/admin` | AdminTools | Yes |
| `/staff/finance` | FinanceManager | Yes |
| `/lyrics/*` | LyricsSession | No |

### 4. `vite.config.js` — Build Configuration
- Vite 5 with `@vitejs/plugin-react`
- No custom aliases, no proxy config

### 5. `vercel.json` — Deployment
- Framework: `vite`, Build: `npm run build`, Output: `dist`
- SPA rewrite: all paths → `/`

# Key Data / Control Flows

## Authentication Flow
```
1. Navigate to /staff/* → ProtectedRoute checks AuthContext
2. AuthContext on mount: getSession() → sets user/loading
3. onAuthStateChange subscription updates user on login/logout
4. Loading → LoadingSpinner | No user → Navigate to /login | User exists → render
5. Login: signInWithPassword(email, password) → navigate('/staff') or setError
6. Logout: signOut() → navigate('/login')
```

## Data Fetching Pattern
```
1. useState([]) for data, useState(true) for loading
2. useEffect → async load function → service call → setState
3. Render: loading → spinner | empty → message + action | data → table/cards
4. Mutations: call service → refetch via loadData()
```
No caching layer, no react-query/SWR, no optimistic updates.

## UI Composition Flow
```
main.jsx
  └─ LocaleProvider
      └─ App (BrowserRouter)
          └─ AuthProvider
              └─ Routes
                  ├─ LandingPage     ← public-home feature (orchestrator)
                  ├─ Login           ← auth feature
                  ├─ LyricsSession   ← lyrics feature (orchestrator)
                  ├─ StaffHub        ← dashboard feature (StaffLayout wrapper)
                  ├─ MemberManager   ← members feature (StaffLayout wrapper)
                  ├─ ContentManager  ← content feature (StaffLayout wrapper)
                  ├─ AdminTools      ← admin-tools placeholder
                  └─ FinanceManager  ← finance feature (StaffLayout wrapper)
```

Protected pages use `StaffLayout` which internally calls `useAuth().signOut`. Staff pages are English-only (hardcoded strings). LandingPage uses `useLocale()` for bilingual text.

## Locale Flow
```
LocaleProvider initialises from localStorage (default 'bm')
t(key) = translations[locale][key] || key
toggleLocale() swaps bm↔en, persists, sets <html lang="...">
Used only in LandingPage — staff pages hardcode English
```

# Architectural Notes

- **Shared component library**: `src/components/ui/` has 11 reusable primitives, `src/components/layout/` has StaffLayout. Design tokens still duplicated per-feature as inline objects.
- **Feature modules**: All pages live in `src/features/<domain>/` with extracted sub-components per directory.
- **Service layer**: All Supabase queries isolated in `src/services/`. No direct `supabase.from()` calls in pages.
- **State management**: Each feature page is a local orchestrator owning all useState hooks. Shared hook layer: `useIsMobile`, `useToast`.
- **No `src/pages/` or `src/lib/`** — directories removed after migration.
- **Inline styles**: All styling via inline `style={{}}`. Tailwind CDN underutilised.
- **No CSS files**, no TypeScript, no tests, no error boundaries.
- **Google Fonts**: Single `<link>` in `index.html` (was duplicated across 6 pages).
