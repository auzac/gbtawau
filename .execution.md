# Runtime Execution Model — GBT Church App

This document traces the exact runtime behavior of the application: call chains, event triggers, data flow sequences, state transitions, and user-interaction-to-system-response paths. It is derived exclusively from `.map.md` and the source code read during mapping.

---

# 1. Boot Sequence Execution (App Initialization)

## Phase 1: Browser → HTML Shell

```
1. Browser requests "/" (or any path — Vercel SPA rewrite serves index.html)
2. HTML parser begins
3. <head> parsed:
   a. <meta charset="UTF-8"> — encoding set
   b. <meta viewport> — mobile viewport set
   c. <title> — tab title "Gereja Baptis Tawau"
   d. <script src="https://cdn.tailwindcss.com"> — network fetch begins (render-blocking)
      → Tailwind CDN executes, scans DOM for classes, injects CSS
   e. <style> block — empty, no-op
4. <body> parsed:
   a. <div id="root"> — empty mount point, empty DOM node
   b. <script type="module" src="/src/main.jsx"> — Vite module fetch begins
```

## Phase 2: JavaScript Bootstrap

```
5. Vite dev server resolves /src/main.jsx → transforms JSX → serves ESM
6. Module dependency tree resolves (all imports loaded before execution):
   main.jsx imports:
     react          → React (namespace, StrictMode)
     react-dom      → ReactDOM (createRoot)
     ./App.jsx      → App (default export)
     ./contexts/LocaleContext → LocaleProvider (named export)
   
   App.jsx imports (recursively):
     react-router-dom → BrowserRouter, Routes, Route, Navigate
     ./contexts/AuthContext → AuthProvider, useAuth
     ./pages/LandingPage → LandingPage (default)
     ./pages/Login → Login (default)
     ./pages/StaffHub → StaffHub (default)
     ./pages/MemberManager → MemberManager (default)
     ./pages/ContentManager → ContentManager (default)
     ./pages/AdminTools → AdminTools (default)
     ./pages/FinanceManager → FinanceManager (default)
     ./pages/LyricsSession → LyricsSession (default)
   
   AuthContext.jsx imports:
     react → createContext, useContext, useEffect, useState
     ../lib/supabase → supabase (singleton client)

   LocaleContext.jsx imports:
     react → createContext, useState, useContext, useEffect
     ../locales/bm.json → bm (parsed JSON object)
     ../locales/en.json → en (parsed JSON object)

   supabase.js imports:
     @supabase/supabase-js → createClient
     Reads import.meta.env.VITE_SUPABASE_URL
     Reads import.meta.env.VITE_SUPABASE_ANON_KEY
     → Throws Error if either is missing (app crashes at import time, no UI)

   All 8 page files import their lucide-react icons, supabase.js, etc.
   → Each import tree fully resolves before any component code runs

7. All modules evaluated, exports registered. No rendering yet.
```

## Phase 3: React Mount

```
8. main.jsx body executes:
   a. ReactDOM.createRoot(document.getElementById('root'))
      → Creates React 18 concurrent root on #root DOM node
   
   b. root.render(
        <React.StrictMode>
          <LocaleProvider>
            <App />
          </LocaleProvider>
        </React.StrictMode>
      )
      
      → React 18 StrictMode: effects fire twice in development (noted for debugging,
        not a production behavior difference)

9. Component tree mounts (synchronous render pass):

   STEP 9a — LocaleProvider mounts:
     - useState(() => localStorage.getItem('locale') || 'bm')
       → Reads 'locale' key from localStorage
       → Default 'bm' if null/missing
       → locale = 'bm' | 'en'
     
     - t = (key) => translations[locale][key] || key
       → Function created, closed over locale
       → translations = { bm: {40 keys}, en: {40 keys} } (from JSON imports)
     
     - toggleLocale function created (not called yet)
     
     - useEffect fires (cleanup/setup):
       → document.documentElement.lang = locale === 'bm' ? 'ms' : 'en'
       → Sets <html lang="ms"> or <html lang="en">
     
     - Context value assembled: { locale, t, toggleLocale }
     - Renders <LocaleContext.Provider value={...}><App /></LocaleContext.Provider>

   STEP 9b — App mounts (child of LocaleProvider):
     - <BrowserRouter> mounts:
       → Creates history object (window.history wrapper)
       → Subscribes to popstate event
       → Reads current URL from window.location
     
     - <AuthProvider> mounts (child of BrowserRouter):

       LINE-BY-LINE inside AuthProvider:
       
       A. const [user, setUser] = useState(null)
          → user = null (initial)
       
       B. const [loading, setLoading] = useState(true)
          → loading = true (initial)
       
       C. useEffect(() => { ... }, []) — fires AFTER render commit:

          C1. supabase.auth.getSession()
              → HTTP GET to Supabase Auth API
              → Reads stored JWT from browser (localStorage/cookie, managed by Supabase SDK)
              → Returns { data: { session } }
              → session = { user: { id, email, ... } } | null
          
          C2. setUser(session?.user ?? null)
              → If session exists: user = session.user object
              → If no session: user = null
          
          C3. setLoading(false)
              → loading = false
          
          C4. const { data: { subscription } } = supabase.auth.onAuthStateChange(
                (_event, session) => {
                  setUser(session?.user ?? null)
                  setLoading(false)
                }
              )
              → Registers listener with Supabase SDK
              → On any auth change (SIGNED_IN, SIGNED_OUT, TOKEN_REFRESHED, USER_UPDATED):
                → setUser(session?.user ?? null)
                → setLoading(false)
              → Supabase SDK internally uses storage events / polling to detect changes
          
          C5. return () => subscription.unsubscribe()
              → Cleanup: removes auth state listener on unmount

       D. signOut = async () => {
            await supabase.auth.signOut()
              → HTTP POST to Supabase Auth API (sign out)
              → Clears JWT from storage
            setUser(null)  // immediately nullifies local state
          }
       
       E. return (
            <AuthContext.Provider value={{ user, loading, signOut }}>
              {children}
            </AuthContext.Provider>
          )
          → children = <AppRoutes />

     STEP 9c — AppRoutes mounts (child of AuthProvider):
       - <Routes> evaluates current URL against route table
       - Route path="/" element={<LandingPage />} matches (for URL "/")
       - <LandingPage /> instantiated
       
       - ProtectedRoute wrapper for /staff/* NOT evaluated yet
         (URL doesn't match those paths)
```

## Phase 4: First Render Complete → Async State Settles

```
10. Browser paints initial UI (LoadingPage spinner OR login redirect)
    
11. getSession() promise resolves (from step C1):
    → setUser(session?.user ?? null)  [step C2]
    → setLoading(false)                [step C3]
    → React batches these setState calls into one re-render
    
12. Re-render propagates:
    - AuthProvider re-renders with loading=false, user=value
    - AppRoutes re-renders with new context value
    - ProtectedRoute (if on /staff/* route) evaluates:
      → if loading → spinner (now false, so skipped)
      → if !user → Navigate to /login (if no session)
      → else → render children (protected page)
    - If on "/": LandingPage unaffected by auth context change
      (LandingPage does not consume useAuth)
    
13. Page-level useEffect hooks now fire (see per-route traces below)
```

## Boot Sequence Summary

```
index.html load
 → Tailwind CDN fetch + execute
 → Vite module /src/main.jsx fetch
 → All imports resolve (react, router, supabase, all 8 pages, 2 contexts, 2 locales)
 → supabase.js validates env vars (throws if missing)
 → createRoot(#root).render()
 → LocaleProvider mount (locale from localStorage, html lang set)
 → BrowserRouter mount (history init)
 → AuthProvider mount (user=null, loading=true)
 → AuthProvider useEffect: getSession() async + onAuthStateChange subscribe
 → Routes match → page component mounts
 → Page component useEffect fires → Supabase data queries
 → getSession() resolves → setUser(), setLoading(false)
 → Re-render → auth-gated routes resolve access/deny
 → App fully interactive
```

```
TRIGGER: URL matches "/" in AppRoutes

1. <Route path="/" element={<LandingPage />} /> resolves
2. LandingPage component function executes (first render):

   STATE INITIALIZATION (14 useState calls):
   ┌─────────────────────────────────────────────────────────┐
   │ menuOpen    = false        UI: hamburger menu         │

   │ verse       = {ref:'',text:'',theme:''}  Data: active verse │
   │ events      = []           Data: upcoming events       │
   │ carouselItems = []         Data: hero carousel slides  │
   │ isEventsModalOpen = false  UI: events modal            │
   │ selectedEvent     = null   UI: event detail drill-down │
   │ isRosterModalOpen = false  UI: roster modal            │
   │ rosters           = []     Data: all roster records    │
   │ rosterMap         = {}     Derived: month→roster map   │
   │ availableMonths   = []     Derived: months with data   │
   │ selectedMonth     = ''     UI: roster month picker     │
   │ selectedWeek      = 1      UI: roster week picker      │
   └─────────────────────────────────────────────────────────┘

   REFS (2 useRef):
   - whatsOnSplideRef = null — Splide carousel instance ref
   - howWeSplideRef   = null — Splide carousel instance ref

   DERIVED VALUES:
   - navigate     = useNavigate()       — router navigate function
   - { t, locale, toggleLocale } = useLocale() — translation context

3. FIRST RENDER (loading = true):
   → Returns spinner div:
     <div className="min-h-screen bg-[#F5EFE6] flex items-center justify-center">
       <div className="w-8 h-8 border-2 border-black/10 border-t-black rounded-full animate-spin" />
     </div>
   → Browser paints spinner
   → User sees: white screen with spinning circle

4. useEffect(() => { loadContent() }, []) — FIRES AFTER COMMIT:

   loadContent() executes:
   
   STEP 4a: setLoading(true)  [already true, no-op re-render]
   
   STEP 4b: await Promise.all([...]) — 4 concurrent Supabase queries:
   
   QUERY 1: loadActiveVerse()
     supabase.from('verse_library')
       .select('*')
       .eq('is_active', true)
       .maybeSingle()
     → HTTP GET to Supabase REST API
     → WHERE is_active = true, LIMIT 1
     → Response: { reference, text, theme } | null
     → setVerse(data) if data exists
     
   QUERY 2: loadUpcomingEvents()
     supabase.from('events')
       .select('*')
       .gte('date', new Date().toISOString().split('T')[0])  // today's date
       .order('date', { ascending: true })
       .order('time', { ascending: true })
     → Returns events from today forward, sorted by date then time
     → setEvents(data)
     
   QUERY 3: loadCarouselItems()
     supabase.from('carousel_items')
       .select('*')
       .eq('is_active', true)
       .order('display_order', { ascending: true })
       .order('created_at', { ascending: true })
     → Returns active carousel slides in display order
     → setCarouselItems(data) if data.length > 0, else setCarouselItems([])
     
   QUERY 4: loadRosters()
     supabase.from('roster')
       .select('*')
       .order('week_start', { ascending: true })
     → Returns ALL roster records (no date filter)
     → CLIENT-SIDE processing:
       a. Iterates every roster row
       b. Parses week_start date string
       c. Calculates UTC-based week number (1-4) within month
       d. Builds rosterMap: { "2024-05-3": rosterObj }  (year-month-week → roster)
       e. Builds availableMonths: [{ value: "2024-05", label: "May 2024" }]
       f. Sets selectedMonth = first available month
       g. setRosters(data), setRosterMap(map), setAvailableMonths(months), setSelectedMonth(firstMonth)

   STEP 4c: setLoading(false)
   
5. RE-RENDER (loading = false):
   → Component renders FULL page markup (~840 lines of JSX)
   → All sections rendered: navbar, hero, about, how-we-do, marquee, giving, footer
   → Conditional sections:
     - Hero video shows if !videoError, else fallback image (backdrop.webp)
     - "What's On" carousel shows if carouselItems.length > 0
     - About verse shows active verse OR fallback from translations
     - How We Do carousel always shows (hardcoded placeholder cards)
     - Events modal NOT rendered (isEventsModalOpen = false)
     - Roster modal NOT rendered (isRosterModalOpen = false)
   → Google Fonts <link> injected into DOM (Darker Grotesque + DM Sans)

6. POST-RENDER: Splide Carousel Effects Fire (2 useEffects):

   EFFECT A: "What's On" Splide (dependency: [carouselItems.length])
     IF carouselItems.length === 0 → return (no-op)
     ELSE:
       a. await setTimeout(150ms) — wait for DOM paint
       b. document.getElementById('whats-on-splide') — find splide root
       c. IF element found:
          - const Splide = (await import('@splidejs/splide')).default
            → DYNAMIC IMPORT: Splide JS bundle loaded on-demand (code split)
          - new Splide(el, { perPage:1, speed:900, rewind:true, arrows:false, pagination:false })
          - splide.mount() → Splide initializes, clones slides, adds ARIA, starts autoplay
          - Manual arrow button handlers wired:
            .whats-on-arrow-prev → splide.go('<')
            .whats-on-arrow-next → splide.go('>')
       d. Cleanup: splide.destroy() on dependency change or unmount

   EFFECT B: "How We Do Church" Splide (dependency: [])
     Same pattern as A but:
       - await setTimeout(200ms)
       - perPage: 3 (desktop), breakpoints: 1024→2, 640→1
       - Only fires once on mount (empty dep array)
       - Cleanup: splide.destroy() on unmount

7. SCROLL HANDLER EFFECT:
   useEffect(() => {
     const onScroll = () => setScrolled(window.scrollY > 40)
     window.addEventListener('scroll', onScroll, { passive: true })
     return () => window.removeEventListener('scroll', onScroll)
   }, [])
   → Every scroll event: setScrolled(true/false)
   → Triggers re-render → nav background toggles white/transparent

8. BODY SCROLL LOCK EFFECT:
   useEffect(() => {
     document.body.style.overflow = (menuOpen || isEventsModalOpen || isRosterModalOpen) ? 'hidden' : ''
     return () => { document.body.style.overflow = '' }
   }, [menuOpen, isEventsModalOpen, isRosterModalOpen])
   → When ANY modal or menu opens → body scroll disabled
   → When ALL close → body scroll restored

9. PAGE NOW FULLY INTERACTIVE.

USER INTERACTIONS on LandingPage (traced individually):

[A] User clicks hamburger "Menu" button:
    → setMenuOpen(o => !o) — toggles boolean
    → nav button style swaps (Menu↔Close, background black↔white)
    → Fullscreen overlay appears with animation (opacity + translate-y stagger on links)
    → body scroll locked (effect 8)
    → User clicks nav link OR closes menu → setMenuOpen(false) → overlay hides

[B] User clicks BM/EN toggle:
    → toggleLocale() from LocaleContext
    → locale swaps bm↔en
    → localStorage.setItem('locale', newLocale)
    → setLocale(newLocale) → LocaleProvider re-renders → t() returns different strings
    → LandingPage re-renders with new translations
    → html lang attribute updates

[C] User clicks "Events" button (in nav modal or about section):
    → openEventsModal() fires:
       setSelectedEvent(null)  → detail view reset
       setIsEventsModalOpen(true) → modal opens
    → Events modal renders:
       - If events.length === 0: "No upcoming events" message
       - If events.length > 0: scrollable list of event cards
         • Each card: date badge, title, dayName + time, chevron
    → User clicks an event card:
       setSelectedEvent(event)
       → Detail view: back button, full event info (date, time, location, PIC, description)
    → User clicks "Close" or X:
       closeEventsModal() → setIsEventsModalOpen(false), setSelectedEvent(null)
    → User clicks outside modal: same close handler (onClick on overlay)

[D] User clicks "Roster" button:
    → openRosterModal() fires:
       setIsRosterModalOpen(true)
    → Roster modal renders:
       - Month selector <select> with availableMonths
       - Week selector: 4 pill buttons (1, 2, 3, 4)
       - Roster card: leader, pianist, reader OR "No roster" message
    → User changes month:
       setSelectedMonth(e.target.value)
       → rosterForSelectedWeek re-computed from rosterMap
       → Card updates to new month's week 1 (or stays on current week)
    → User changes week:
       setSelectedWeek(w)
       → rosterForSelectedWeek re-computed
       → Card updates

[E] Video error:
    → onError={() => setVideoError(true)}
    → Re-render: video element replaced by background-image div (backdrop.webp)

[F] User clicks "Give now" / "Learn more":
    → <a href="#"> — page scrolls to top (hash-only links, no handlers)
```

# 3. Authentication Execution Lifecycle

## Phase A: Initial Session Hydration

```
1. AuthProvider mounts with loading=true, user=null
2. useEffect fires (empty dep array):

   STEP 2a: supabase.auth.getSession() — ASYNC, PROMISE PENDING
     → Supabase SDK checks localStorage/cookie for stored JWT
     → If JWT exists: validates with Supabase Auth server (or uses cached session)
     → Returns { data: { session: { user, expires_at, ... } } } | { data: { session: null } }

   STEP 2b: supabase.auth.onAuthStateChange(callback) — SYNCHRONOUS SUBSCRIPTION
     → Registers callback with Supabase SDK
     → SDK internally listens to:
       - Storage events (for cross-tab sync)
       - PostMessage events
       - Timer-based token refresh
     → Returns { data: { subscription } }
     → Callback signature: (_event, session) => {
         setUser(session?.user ?? null)
         setLoading(false)
       }
     → Events: SIGNED_IN, SIGNED_OUT, TOKEN_REFRESHED, USER_UPDATED, PASSWORD_RECOVERY

3. PROMISE RESOLVES (step 2a):
   → setUser(session?.user ?? null)
   → setLoading(false)
   → React batches → single re-render
   → All ProtectedRoute components re-evaluate:
     loading=false → check user → grant/deny access

4. EITHER RESULT:
   Session exists:
     → user = { id, email, ... } (Supabase User object)
     → Protected routes render children
     → Staff pages mount and fetch data
   
   No session:
     → user = null
     → Protected routes redirect to /login
     → Public routes render normally
```

## Phase B: Auth State Change Listener (Runtime)

```
SUPABASE SDK triggers callback on:

SIGNED_IN:
  → After successful signInWithPassword() in Login.jsx
  → SDK receives new JWT, stores it
  → Callback: setUser(session.user), setLoading(false)
  → user already set (session.user) — re-render with confirmed user object
  → navigate('/staff') has already fired from Login handleSubmit

SIGNED_OUT:
  → After supabase.auth.signOut() in AuthContext.signOut()
  → SDK clears JWT from storage
  → Callback: setUser(null), setLoading(false)
  → Already set to null in signOut() function — re-confirms null

TOKEN_REFRESHED:
  → SDK detects JWT expiring, auto-refreshes with Supabase
  → Callback: setUser(session.user) — user object updated with new token
  → No visible UI change (user object identity same, token different)

USER_UPDATED:
  → If user profile changes (email, password, metadata)
  → Callback: setUser(updated user object)
  → Currently not triggered by any app code (no user profile editing feature)
```

## Phase C: Login Flow (Complete Trace)

```
TRIGGER: User submits email + password on /login

1. Login.handleSubmit(e):
   a. e.preventDefault()
   b. setError('') — clear previous
   c. setIsLoading(true) — disable form, show spinner

2. await supabase.auth.signInWithPassword({ email, password })
   → HTTP POST to Supabase Auth REST endpoint
   → Request body: { email, password }
   → Supabase validates credentials against auth.users table
   
   SUCCESS RESPONSE:
     { data: { user, session }, error: null }
     → JWT token in session.access_token
     → Supabase SDK stores token in browser storage
     → SDK emits SIGNED_IN event internally (not yet propagated to callback)
   
   FAILURE RESPONSE:
     { data: null, error: { message: "Invalid login credentials" } }

3. IF ERROR:
   a. setError(signInError.message) → error div renders
   b. setIsLoading(false) → form re-enabled
   c. User stays on /login page
   d. END

4. IF SUCCESS:
   a. navigate('/staff') → React Router navigates
   b. URL changes to /staff
   c. AppRoutes re-evaluates:
      → Route path="/staff" matches
      → ProtectedRoute fires:
        → Reads AuthContext
        → At this instant, getSession() from initial mount already cached
          OR onAuthStateChange has fired and set user
        → loading should be false, user should be object
        → Renders StaffHub
   d. StaffHub mounts, starts its data fetching (see /staff trace)

   TIMING NOTE: There is a potential race condition:
     navigate('/staff') fires immediately after successful supabase call
     But onAuthStateChange may not have fired yet
     If getSession() was called during initial AuthProvider mount and returned null
     (because user wasn't logged in then), the AuthContext still has user=null
     
     HOWEVER: Supabase's signInWithPassword returns the session in the response,
     AND internally caches it. The getSession() method would return the cached
     session. BUT AuthProvider's getSession() is only called once on mount (empty deps).
     
     So the flow relies on onAuthStateChange firing before or during the navigation.
     If there's a timing gap, ProtectedRoute sees user=null and redirects to /login,
     then onAuthStateChange fires → user set → but user is already at /login.
     
     In practice: Supabase SDK typically fires onAuthStateChange synchronously
     (or near-synchronously) after signInWithPassword resolves, before the
     next React render cycle. So user state should be set when ProtectedRoute checks.
     But the code has no explicit guard for this race.
```

## Phase D: Logout Flow (Complete Trace)

```
TRIGGER: User clicks "Sign out" on any staff page

1. handleLogout() fires:
   → await signOut()  [from AuthContext]
   → navigate('/login')

2. Inside AuthContext.signOut():
   a. await supabase.auth.signOut()
      → HTTP POST to Supabase Auth endpoint (sign out)
      → Supabase invalidates token server-side
      → SDK clears JWT from browser storage
      → SDK emits SIGNED_OUT event
   b. setUser(null) — immediate local state clear
      → This is marked "CRITICAL" in source — ensures UI reacts immediately
   
3. onAuthStateChange callback also fires:
   → _event = 'SIGNED_OUT', session = null
   → setUser(null) — confirms null (idempotent)
   → setLoading(false) — already false

4. navigate('/login') fires:
   → URL changes
   → Login page renders
   → User sees login form

5. Cleanup: The staff page's component unmounts
   → Any cleanup effects run (event listeners, etc.)
   → Supabase subscriptions? Only the onAuthStateChange listener in AuthProvider
     remains active (AuthProvider does NOT unmount — it wraps the entire app)
   → AuthProvider stays mounted, user=null

6. ON ALL STAFF PAGES: The signOut function is obtained via useAuth()
   → Every protected page imports useAuth and calls signOut on its logout button
   → Pattern is identical across StaffHub, MemberManager, ContentManager, FinanceManager:
     const { signOut } = useAuth()
     const handleLogout = async () => { await signOut(); navigate('/login') }
```

## Phase E: Protected Route Enforcement (At Runtime)

```
TRIGGER: Any navigation to /staff, /staff/*, or initial load on protected URL

1. <Route path="/staff" element={<ProtectedRoute><StaffHub /></ProtectedRoute>} />
2. ProtectedRoute executes:
   
   const { user, loading } = useAuth()
   → Subscribes to AuthContext
   → Re-renders on any AuthContext value change

   RENDER BRANCHES (evaluated on EVERY render):

   BRANCH A: loading === true
     → AuthProvider still resolving getSession()
     → Return spinner
     → User sees loading animation
     → Duration: typically < 500ms (local JWT validation) or < 2s (network validation)
     → When getSession() resolves → loading=false → re-evaluate

   BRANCH B: loading === false, user === null
     → No authenticated user
     → Return <Navigate to="/login" replace />
     → React Router replaces current URL with /login
     → Login page renders
     → REPLACE means back button skips the protected URL

   BRANCH C: loading === false, user !== null
     → Authenticated
     → Return children (the protected page component)
     → Page mounts and begins data fetching

3. RE-AUTHENTICATION SCENARIO:
   → User is on /staff/members (authenticated)
   → JWT expires
   → Supabase SDK attempts token refresh (TOKEN_REFRESHED event)
   → If refresh succeeds: user stays logged in, no visible change
   → If refresh fails: SDK emits SIGNED_OUT event
     → AuthContext: setUser(null), setLoading(false)
     → ProtectedRoute re-renders: loading=false, user=null
     → <Navigate to="/login" replace />
     → User is ejected to login page
```

# 6. Cross-System Runtime Interactions

## 6.1 AuthContext ↔ App Routing

```
AuthProvider mounts INSIDE BrowserRouter, OUTSIDE Routes
  → BrowserRouter provides routing context
  → AuthProvider provides auth context
  → AppRoutes is child of AuthProvider

ProtectedRoute reads AuthContext via useAuth() hook:
  → Every render: reads user + loading
  → Auth state change → AuthProvider re-renders → ProtectedRoute re-renders
  → ProtectedRoute does NOT subscribe to routing — it's purely auth-gated

INTERACTION 1 — Initial load on /staff:
  BrowserRouter resolves URL → Route matches /staff
  → ProtectedRoute checks AuthContext: loading=true → spinner
  → getSession() resolves → user set → AuthProvider re-renders
  → ProtectedRoute re-renders: loading=false, user=object → renders StaffHub

INTERACTION 2 — Sign in:
  Login → supabase.auth.signInWithPassword() → navigate('/staff')
  → onAuthStateChange fires (SIGNED_IN) → AuthContext updates user
  → Route change + auth change occur near-simultaneously
  → ProtectedRoute re-evaluates: user present → grants access

INTERACTION 3 — Sign out:
  Any staff page → handleLogout() → signOut() + navigate('/login')
  → AuthContext: user set to null
  → Route changes to /login
  → AuthProvider stays mounted but user=null
  → Public routes work; /staff/* ProtectedRoutes would redirect

INTERACTION 4 — Token expiry during session:
  Supabase SDK detects expiring JWT
  → Attempts TOKEN_REFRESHED
  → On success: AuthContext updates user (new token)
  → On failure: SIGNED_OUT → user=null
  → ProtectedRoute(s) re-render → Navigate to /login
  → User is force-logged-out on whatever page they were on
```

## 6.2 LocaleContext ↔ LandingPage Rendering

```
LocaleProvider wraps entire app (outermost provider)
  → locale state from localStorage (default 'bm')
  → t() function: translations[locale][key]
  → toggleLocale(): swaps locale, updates localStorage, sets html lang

LandingPage is the ONLY consumer of useLocale()
  → All text rendered via t() calls: t('about_tagline'), t('events_button'), etc.
  → Fallback: if key not found in translations, returns key string itself
  → English hardcoded fallbacks: t('key') || 'English fallback'

STAFF PAGES do NOT use useLocale()
  → All strings are hardcoded in English
  → No bilingual support for staff UI

INTERACTION:
  User clicks BM/EN button → toggleLocale()
  → LocaleProvider re-renders
  → LandingPage re-renders (useLocale consumer)
  → All t() calls return new language strings
  → HTML lang attribute changes
  → Roster modal re-renders: month names change locale
    (new Date().toLocaleString(locale === 'bm' ? 'ms-MY' : 'en-US', ...))
```

## 6.3 Supabase ↔ All Page Components

```
supabase.js → singleton client → imported by 8 page files + AuthContext

RUNTIME BEHAVIOR:
  - Supabase SDK internally manages:
    • JWT storage (localStorage by default)
    • Token refresh timers
    • Request retries
    • Connection pooling / keep-alive
  - No custom interceptors or middleware in app code
  - No request caching — every query is a fresh HTTP request
  - No offline support
  - No optimistic updates
  - No request deduplication between components

INTER-COMPONENT DATA STALENESS:
  LandingPage and ContentManager independently fetch the same tables:
    → verse_library (active verse)
    → events (upcoming)
    → carousel_items (active)
    → roster (all)

  Changes in ContentManager do NOT propagate to LandingPage:
    → No shared state
    → No event bus
    → No Supabase realtime subscriptions
    → No React context for content data
    → User must manually refresh browser to see changes on LandingPage

  Similarly, FinanceManager and StaffHub both fetch membership_renewals:
    → StaffHub shows count on dashboard
    → FinanceManager shows full table
    → Recording a payment in FinanceManager does NOT update StaffHub's count
      until user navigates back to StaffHub (which refetches on mount)
```

## 6.4 LyricsSession ↔ Multi-Table Join

```
public_sessions (parent)
  │
  ├── session_code (unique, 4-digit string)
  ├── expires_at (nullable timestamp)
  ├── created_at (timestamp)
  │
  └── session_songs (child, FK: session_id → public_sessions.id)
       │
       ├── session_id
       ├── song_id (FK → songs.id)
       │
       └── songs (referenced)
            ├── id
            ├── title
            └── lyrics (text with \n line breaks)

JOIN EXECUTION (APP-LEVEL, NOT SQL JOIN):

CREATE: 
  1. INSERT public_sessions → get id
  2. INSERT session_songs (batch) using id

JOIN (session lookup):
  1. SELECT public_sessions WHERE session_code = X → get session.id
  2. SELECT session_songs WHERE session_id = X → get [song_id, ...]
  3. SELECT songs WHERE id IN ([song_id, ...]) → get song data
  → THREE sequential Supabase queries
  → Not a SQL JOIN — app-level composition

RACE CONDITION: Between session creation and joining:
  - User creates session, navigates to /lyrics/join/CODE
  - Another user enters same code
  - If navigate fires before INSERT completes on Supabase:
    join query finds no session → "Session not found"
  - Mitigated: navigate() called AFTER all inserts succeed (in handleCreate)
```

## 7.2 Repeated Re-Fetch Loops

```
EVERY CRUD operation follows:
  1. Mutation (INSERT/UPDATE/DELETE) over HTTP
  2. On success: call loadData() / loadAll() / loadMembers()
  3. Which issues fresh SELECT of ENTIRE dataset
  4. Which triggers setState with new array
  5. Which triggers full re-render

THERE ARE NO:
  - Local state updates after mutation (optimistic or otherwise)
  - Incremental additions to arrays (no setMembers(prev => [...prev, newMember]))
  - Cache invalidation patterns beyond "refetch everything"
  - Request deduplication

EVERY MUTATION results in:
  → 1 HTTP write (mutation)
  → 1+ HTTP reads (full dataset refetch)
  → Full component re-render

EXAMPLES:
  MemberManager: deleting 1 member → DELETE request + SELECT * request
  ContentManager: adding 1 event → INSERT request + 5 SELECT * requests (loadAll)
  FinanceManager: recording 1 payment → INSERT request + 2 SELECT * requests (loadData)
```

# Execution Summary

The app follows a consistent runtime pattern:

1. **Boot**: HTML → Vite → React tree → LocaleProvider → BrowserRouter → AuthProvider → Routes
2. **Auth**: getSession() async hydration → ProtectedRoute gate → staff access granted/denied
3. **Data**: Every page fetches its own data on mount via useEffect → supabase → useState → render
4. **Mutation**: User action → local state update OR Supabase mutation → refetch entire dataset → full re-render
5. **State**: No shared state between pages (except AuthContext + LocaleContext). No caching. No realtime subscriptions. Each page is a self-contained data island.
6. **Navigation**: React Router client-side routing. Pages unmount/mount on navigation (except /lyrics/* catch-all). All component state is lost on navigation away.
