# System Context — GBT Church App

A single-page web application for **Gereja Baptis Tawau** (GBT Church, Tawau, Sabah, Malaysia). Built with Vite + React 18, Supabase (PostgreSQL + Auth), Tailwind CSS via CDN, deployed on Vercel. Serves dual purpose: public church website + password-protected internal staff portal.

---

## Phase 1: `.map.md` — Structural Map

**Purpose**: Forensic-level structural and functional map of the codebase — what exists and where.

**Key findings**:
- 8 page components (1174 LOC max), 2 React contexts, 1 Supabase client singleton
- `src/components/` is empty — no shared components extracted
- All styling via inline style objects, Tailwind CDN (not build-time JIT)
- Route table: `/` (LandingPage), `/login` (Login), `/staff` (StaffHub), `/staff/members` (MemberManager), `/staff/content` (ContentManager), `/staff/admin` (AdminTools), `/staff/finance` (FinanceManager), `/lyrics/*` (LyricsSession)
- 9 Supabase tables inferred from queries: verse_library, events, carousel_items, roster, members, membership_renewals, songs, public_sessions, session_songs
- No TypeScript, no testing, no error boundaries, no caching layer
- No React Router data loaders — all data fetching via `useEffect` + `useState`

**Content**: Directory tree, system breakdown (4 layers), route table, Supabase schema inference, dependency graph, module index, data/control flow diagrams.

## Phase 2: `.execution.md` — Runtime Execution Model

**Purpose**: Trace how the system behaves when actually running — call chains, event triggers, state transitions, user interaction paths.

**Key findings**:
- **Boot sequence**: 4 phases — HTML shell → Vite module resolution → React mount (LocaleProvider → BrowserRouter → AuthProvider → Routes → page) → async state settlement
- **Auth lifecycle**: getSession() async hydration → onAuthStateChange listener → race condition between navigate('/staff') and state update
- **Data pattern**: Every page independently fetches all data on mount via `useEffect → supabase → useState`. No shared cache. No deduplication.
- **Mutation pattern**: Every CRUD → full dataset refetch → full re-render. ContentManager's loadAll() refetches 5 independent queries on any single change.
- **Cross-page staleness**: ContentManager changes invisible to LandingPage. FinanceManager changes invisible to StaffHub. No synchronization mechanism.
- **Re-render hotspots**: 7 identified — scroll handler (60fps), search keystrokes (no debounce), FinanceManager O(n²) computations, isMobile resize, etc.
- **Race conditions**: Login navigate vs onAuthStateChange; verse activation gap window (non-transactional two-step UPDATE)
- **14 systemic risks catalogued** with severity ratings

**Content**: 7 major sections — boot sequence, all 6 route execution traces, auth lifecycle (5 phases), 6 data flow graphs, CRUD execution chains, cross-system interactions, re-render hotspot inventory.

## Phase 3: `.audit.md` — Architecture Diagnosis

**Purpose**: System-level architectural diagnosis combining structural analysis with runtime behavior.

**Architectural classification**: **Tightly-coupled UI-data execution mesh** — pages are not consumers of a data layer, they ARE the data layer, business logic, and UI fused into single files.

**4 structure-vs-runtime mismatches identified**:
1. Modular structure (8 separate pages) → Monolithic execution (every page duplicates identical patterns)
2. "Data Access Layer" (lib/supabase.js) → 11-line configuration export with zero abstraction
3. Route independence → Hidden database-mediated coupling between pages
4. "State Management" contexts → Two thin wrappers with no real orchestration

**Key risks** (14 total, 3 high severity):
- **R1**: Cross-page data inconsistency (ContentManager ↔ LandingPage, FinanceManager ↔ StaffHub)
- **R7**: No error boundaries — uncaught error crashes entire component tree
- **R8**: Missing env vars crash at module import time with no UI fallback
- **R2**: Login race condition (navigate vs auth state)
- **R11**: O(n²) FinanceManager hasPaidForYear computation per render

**Root causes**: Page-as-application pattern, no data layer abstraction, missing React infrastructure (error boundaries, navigation guards, suspense).

## Phase 4: `.plan.md` — Migration Plan

**Purpose**: Controlled, incremental transformation roadmap from current reality → production-grade modular architecture. Preserves entire stack (React/Vite/Supabase). No new frameworks.

**Target**: Feature-based modular SPA — reorganize existing code into modules with defined boundaries.

**Final folder structure**: `features/` (domain modules), `components/ui/` + `components/layout/`, `services/` (data layer), `hooks/` (shared hooks), `contexts/` (preserved).

**6 migration steps**:
1. **Zero-risk UI extraction** — Populate empty `components/` with LoadingSpinner, Modal, Toast, Badge, StatCard, SearchInput. Pure copy-paste, no behavioral change. LOW risk.
2. **Shared hook consolidation** — Extract useIsMobile (5 copies → 1), useToast (3 copies → 1). LOW risk.
3. **Service layer introduction** — Move all direct Supabase queries into `services/` modules. Exact query preservation — no transformations, no caching. MEDIUM risk.
4. **Feature modularization** — Decompose 1000+ LOC files into feature directories with sub-components. Smallest features first, LandingPage last. MEDIUM risk.
5. **Staff layout extraction** — Unify sidebar/header/logout pattern across 4 staff pages via StaffLayout. LOW-MEDIUM risk.
6. **Auth guard stabilization** — Fix login race condition. OPTIONAL, deferred last. MEDIUM risk.

**Refactor boundaries** (do not touch until specified step):
- AuthContext/ProtectedRoute: HIGH risk — do not touch until Step 5-6
- ContentManager.loadAll(): MEDIUM risk — defer until service layer exists
- LandingPage's 4-query Promise.all: MEDIUM risk — defer until feature decomposition
- Auth login race: HIGH risk — defer to last

**Risk strategy**: Each step is a single git commit with clear rollback path. Verification checkpoints between steps. Rollback triggers defined (network errors, data corruption, auth lockout, visual regression, console errors).
